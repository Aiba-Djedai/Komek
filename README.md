# Kömek — платформа для волонтёров Алматы

Работающий MVP по пользовательскому описанию и критериям Assignment7.docx. Интерфейс на русском, казахском и английском языках: каталог проектов, отдельные роли, заявки и подтверждённый состав команды. Данные сохраняются на сервере в SQLite, а не в памяти браузера. Избранное хранится локально в браузере.

## Запуск

Требуется Node.js 24+ и npm. Docker, внешняя БД и ключи API не нужны.

```bash
cd /workspace/Komek
npm ci --cache /tmp/komek-npm-cache
npm run dev
```

Интерфейс: порт **5173**. API: порт **3001**. Оба сервера запускаются одной командой. В обычном локальном окружении проект запускается из каталога репозитория. `npm ci` без параметра `--cache` также подходит, если системный npm-кеш доступен для записи.

Сборка и запуск одним сервером:

```bash
npm run build
npm start
```

После сборки сервер на порту 3001 обслуживает интерфейс, API и прямые ссылки `/events/:id`, `/my-projects` и `/dashboard`.

## Знакомство с платформой

В окне входа есть кнопки **«Волонтёр»** и **«Организация»** для демо-входа:

| Роль        | Email              | Пароль     |
| ----------- | ------------------ | ---------- |
| Волонтёр    | volunteer@komek.kz | Komek2026! |
| Организация | org@komek.kz       | Komek2026! |

Это открытые тестовые аккаунты с вымышленными данными. Для своей работы зарегистрируйте отдельные аккаунты. При первом запуске пустой БД автоматически создаются 7 событий с относительными датами, несколько заявок и уведомление волонтёру. Уже существующие данные при повторном запуске не перезаписываются.

Проверка вручную:

1. Организация регистрируется, открывает кабинет и публикует событие.
2. Волонтёр регистрируется в отдельном браузере/окне инкогнито, находит событие и подаёт заявку с согласием.
3. Организация видит заявку и принимает или отклоняет её.
4. Волонтёр получает уведомление в кабинете и, если одобрен, подтверждает участие.
5. Организация видит его в подтверждённом составе и выгружает CSV выбранного события.

Кабинет обновляется при возвращении в окно, каждые 30 секунд и после собственных действий. Можно обновить страницу вручную.

| Каталог                    | 8 направлений с множественным выбором, город, поиск, актуальные/предстоящие/прошедшие события, ближайшие даты, избранное                                                                    |
| F1 — событие и ссылка      | Название, описание, категория, отдельный город и адрес, дата и время, часы, число мест, дедлайн, фото по HTTPS-ссылке, требования; отдельный URL события; редактирование и ручное закрытие  |

| F2 — решения               | Принять/отказать, автоматическая отметка времени, уведомление в кабинете с правильным решением и следующим шагом                                                                            |
| F2 — вместимость           | Принятые и подтвердившие занимают места; при заполнении сервер блокирует дополнительное принятие и уведомление; можно увеличить вместимость                                                 |
| F2 — сообщения             | Отдельные шаблоны Telegram/email, копирование, отметка о фактической ручной отправке и её время; предупреждения после 44 ч. ожидания и 4 ч. после решения                                   |
| Метрика 48 часов           | В кабинете организации показывается доля всех заявок, для которых внешняя отправка отмечена не позднее 48 ч. после подачи; цель 80%. Встроенные уведомления не выдаются за внешнюю доставку |
| F3 — подтверждённый состав | Только Accepted → подтверждение самим волонтёром → Confirmed; время подтверждения, закрытый список и CSV; неподтвердившие отдельно и с предупреждением за 24 ч.                             |
| NFR1 — приватность         | Заявки и контакты доступны автору заявки и владельцу события; чужие организации и гости не получают состав/CSV; согласие проверяется сервером                                               |
| NFR2 — точность            | Решение и уведомление создаются одной транзакцией; подтверждение запрещено для Pending/Declined; тест с 10 заявками проверяет соответствие сообщений и состава                              |

Прямой запрос пользователя расширяет исходный concierge-MVP: сайт и самостоятельные личные кабинеты реализованы вместо Google Forms/Sheets. Telegram/email остаются ручными, как предусмотрено документом. **Автоматической внешней рассылки нет**: кнопка «Я отправил(а) сообщение» только фиксирует действие организатора. Чат, биллинг, реклама и проверка гипотезы о платёжеспособности не входят в MVP. Целевые показатели 15 организаций за 12 недель и повторных событий за 60 дней требуют настоящего пилота; демо-данные не подтверждают их достижение.

## Главные страницы по ролям

Ветка `feat/platform-improvements` содержит отдельные главные страницы для гостей, волонтёров и организаций:

- **Гость:** заметные кнопки «Найти своё дело» и «Я представляю организацию» сразу открывают регистрацию выбранной роли. В шапке есть отдельная кнопка «Регистрация».
- **Волонтёр:** приветствие, свои заявки, ближайшее участие с подтверждением, показатели участия и каталог проектов.
- **Организация:** создание проекта, свои события, ожидающие решения заявки и переход к подтверждённому составу. Публичный каталог доступен отдельно по `/projects`.
- Роль видна в шапке на всех страницах, включая мобильные экраны. После повторного открытия сайта главная определяется сохранённой авторизованной сессией.

### Мои проекты волонтёра

Страница `/my-projects` доступна волонтёрам через пункт **«Мои проекты»** между «Найти проект» и «Организации» в основном меню, включая мобильную версию.

- **Предстоящие:** события с заявками на рассмотрении, одобренными заявками и подтверждённым участием. Ближайшие события идут первыми; событие в процессе также остаётся здесь до окончания. Одобренную заявку можно подтвердить до начала события.
- **Завершённые:** только события с подтверждённым участием, у которых прошла дата начала плюс указанная длительность в часах. Последние завершившиеся события идут первыми. Это история подтверждённых участий: фактическое посещение в текущем MVP отдельно не отмечается.
- Отклонённые и прошлые неподтверждённые заявки остаются в личном кабинете; со страницы есть переход к ним. Часы завершённых проектов в кабинете используют тот же расчёт окончания.
- Списки используют существующий закрытый API заявок текущего пользователя. Изменение схемы БД и перенос данных не требуются.

Скриншоты: [гостевая страница](docs/screenshots/home.png), [главная волонтёра](docs/screenshots/volunteer.png), [главная организации](docs/screenshots/organization.png).

Исходная версия сохранена в ветке `feat/volunteer-platform-mvp` и метке `mvp-baseline-2026-10-30`. В новой ветке `render.yaml` описывает отдельный демо-сервис `komek-improvements-demo`, подключённый к `feat/platform-improvements`. Развёртывание из новой ветки выполняется отдельно; существующий сервис исходной версии сам на неё не переключается.

## Каталог и направления

К существующим направлениям добавлены **спортивное**, **медицинское** и **поисково-спасательное волонтёрство**. Все восемь направлений доступны при создании и редактировании событий, в фильтрах и на карточках. Названия переведены на RU / KK / EN.

На компьютере фильтры находятся слева от карточек. На экранах до 900 px они свёрнуты в раскрывающийся блок. Выбор применяется сразу:

- Направления отмечаются чекбоксами: проекты любого из выбранных направлений попадают в результаты. Без выбранных направлений показываются все.
- Город выбирается из городов, для которых есть события. Есть «Все города» и, если нужны старым данным, «Город не указан». Город сочетается с направлениями, поиском, периодом и избранным.
- «Сначала ближайшие» включён по умолчанию: будущие события сортируются по возрастанию даты начала, прошедшие — от последних к более давним. Если снять галочку, сначала показываются недавно добавленные проекты. Ручной ввод дат не требуется.
- «Сбросить фильтры» очищает направления, город, поиск и избранное, возвращает актуальные проекты и ближайший порядок. «Все направления» очищает только направления.

В форме организации город указывается отдельно от адреса: можно выбрать предложенный город Казахстана или ввести другой. Известные варианты вроде `Almaty` / `Алматы` и `Қарағанды` / `Караганда` сохраняются под одним названием. Поиск распознаёт эти варианты на трёх языках.

При запуске `openDb` автоматически добавляет `events.city` в прежнюю SQLite-базу. Распознаваемые города заполняются из прежних адресов, остальные остаются без назначенного города и доступны в каталоге. События, пользователи и заявки сохраняются. Повторный запуск не перезаписывает выбранные города; ручной перенос данных не требуется. Старые клиенты без поля города поддерживаются, когда город можно определить из адреса или сохранить при редактировании.

Скриншоты: [каталог с панелью фильтров](docs/screenshots/catalog-filters.png), [фильтры на телефоне](docs/screenshots/catalog-filters-mobile.png).

## Языки интерфейса

В шапке доступен переключатель с глобусом **RU / KK / EN**. По умолчанию используется русский. Выбор сохраняется в `localStorage` (`komek-language`), применяется без перезагрузки и синхронизируется между вкладками. В окнах форм также есть переключатель: введённые данные при смене языка сохраняются. При недоступном хранилище язык можно менять до перезагрузки.

Переведены навигация, страницы обеих ролей, каталог и фильтры, «Мои проекты», формы и их проверки, статусы, уведомления, сообщения API, шаблоны ручной отправки, условия и конфиденциальность. Названия месяцев и формат дат зависят от языка; часовой пояс остаётся `Asia/Almaty`. Заголовки CSV выгружаются на выбранном языке.

Названия и описания событий, имена, контакты и прочие данные авторов сохраняются и отображаются в исходном виде, включая демонстрационные проекты. Смена языка не редактирует БД. Уже сохранённые системные уведомления переводятся по известным шаблонам с сохранением названия события. Внешний сервис перевода не используется.

Скриншоты: [английский интерфейс и меню языков](docs/screenshots/language-menu-en.png), [казахский интерфейс на телефоне](docs/screenshots/language-menu-kk-mobile.png).

- `shared/messages.ts` — единый словарь: русский исходный текст → казахский и английский переводы. Параметры `{0}`, `{1}` подставляются без изменения пользовательских данных.
- `shared/translate.ts` — общий перевод для клиента и API, обработка системных уведомлений и `Accept-Language`.
- `src/lib/i18n.ts` — состояние языка, формат дат, атрибут `html.lang`, заголовок и описание страницы.
- `src/components/LanguageSwitcher.tsx` — выбор языка с управлением клавиатурой и возвратом фокуса. На экранах до 1050 px основная навигация доступна через меню.
- API возвращает локализованный `error` и исходный `source_error`, чтобы текст уже открытой ошибки мог обновиться вместе с языком. CSV принимает `lang=ru`, `lang=kk` или `lang=en`.

## Проверки

```bash
npm test            # 27 проверок API, миграции города, фильтров, переводов и участия
npm run build       # TypeScript и production-сборка
npm run test:e2e    # 19 сценариев Chromium: каталог, роли, заявки, языки, формы и мобильная версия
```

Браузерные тесты сами запускают изолированную пару серверов на 5174/3002 с отдельной временной SQLite-базой; рабочая БД не затрагивается. В облачной среде используется `/usr/bin/chromium`. Для другого пути задайте `CHROMIUM_PATH`. Если Chromium отсутствует, установите его или браузер Playwright и укажите путь.

## Хранение и конфигурация

- `.data/komek.sqlite` и WAL-файлы содержат пользователей, сессии, события, заявки и уведомления. Каталог исключён из Git. Сохраняйте его на постоянном диске и делайте резервные копии средствами SQLite; не копируйте только основной файл при активном WAL.
- `DATABASE_PATH` — необязательный путь к SQLite.
- `PORT` — порт API/production-сервера, по умолчанию 3001. Dev-прокси использует тот же порт.
- `SEED_DEMO=false` — отключить демонстрационные данные **до первого запуска пустой БД**. Для публичного экземпляра создайте отдельную чистую БД с этим параметром.
- `COOKIE_SECURE=true` — для публикации за HTTPS. Cookies HttpOnly и SameSite=Lax; пароли хешируются scrypt с индивидуальной солью; в БД хранится хеш токена сессии. Сессия действует 7 дней. Есть ограничение частоты регистрации/входа и проверка Origin для изменяющих запросов.

Пример запуска чистого экземпляра после сборки:

```bash
SEED_DEMO=false DATABASE_PATH=/persistent/komek.sqlite COOKIE_SECURE=true PORT=3001 npm start
```

Разворачивайте за HTTPS-прокси, сохраняющим исходный Host. Веб-приложение и API должны быть на одном origin. Перед реальным пилотом назначьте оператора персональных данных, укажите его контакт, проверьте согласие и правовые требования, настройте резервное копирование и используйте фотографии, на которые у организации есть права. Тексты в окнах конфиденциальности и условий обозначают статус пилота.

## Посмотреть сайт через Render

В репозитории есть `render.yaml` для демо-сервиса с бесплатным планом. Это конфигурация публикации; сам файл не создаёт сервер и не является подтверждением выполненного развёртывания.

1. Войдите на https://dashboard.render.com/ через GitHub.
2. Выберите **New → Blueprint**, подключите репозиторий `Aiba-Djedai/Komek` и ветку **`feat/platform-improvements`** для новой версии. Для исходной версии используйте **`feat/volunteer-platform-mvp`**. У новой версии своё имя сервиса: `komek-improvements-demo`.
3. Проверьте план **Free** и примените конфигурацию. Render установит Node.js 24, соберёт сайт и запустит API с интерфейсом одним сервером.
4. После успешного развёртывания откройте HTTPS-адрес сервиса, который покажет Render. Демонстрационные аккаунты доступны в окне входа.

Бесплатный сервис подходит для просмотра MVP: его SQLite-файлы временные, данные могут сбрасываться при пересоздании или повторном развёртывании, а первый запрос после простоя может ожидать запуска сервера. Для реальных пользователей нужен постоянный диск или отдельная постоянная база данных. Публичный URL и доступность публикации можно подтвердить только после выполнения развёртывания в аккаунте Render.
