# Kömek — платформа для волонтёров Алматы

Работающий MVP по пользовательскому описанию и критериям Assignment7.docx. Интерфейс на русском языке: каталог проектов, отдельные роли, заявки и подтверждённый состав команды. Данные сохраняются на сервере в SQLite, а не в памяти браузера. Избранное хранится локально в браузере.

## Запуск

Требуется Node.js 24+ и npm. Docker, внешняя БД и ключи API не нужны.

```bash
cd /workspace/Komek
npm ci --cache /tmp/komek-npm-cache
npm run dev
```

Интерфейс: порт **5173**. API: порт **3001**. Оба сервера запускаются одной командой. В обычном локальном окружении проект запускается из каталога репозитория. `npm ci` без параметра `--cache` также подходит, если системный npm-кеш доступен для записи.

Сборка и запуск одним сервером:

```bash
npm run build
npm start
```

После сборки сервер на порту 3001 обслуживает интерфейс, API и прямые ссылки `/events/:id` и `/dashboard`.

## Знакомство с платформой

На странице входа раскройте **«Попробовать демо»**. Там есть кнопки **«Волонтёр»** и **«Организация»**:

| Роль        | Email              | Пароль     |
| ----------- | ------------------ | ---------- |
| Волонтёр    | volunteer@komek.kz | Komek2026! |
| Организация | org@komek.kz       | Komek2026! |

Это открытые тестовые аккаунты с вымышленными данными. Для своей работы зарегистрируйте отдельные аккаунты. При первом запуске пустой БД автоматически создаются 7 событий с относительными датами, несколько заявок и уведомление волонтёру. Уже существующие данные при повторном запуске не перезаписываются.

Проверка вручную:

1. Организация регистрируется, открывает кабинет и публикует событие.
2. Волонтёр регистрируется в отдельном браузере/окне инкогнито, находит событие и подаёт заявку с согласием.
3. Организация видит заявку и принимает или отклоняет её.
4. Волонтёр получает уведомление в кабинете и, если одобрен, подтверждает участие.
5. Организация видит его в подтверждённом составе и выгружает CSV выбранного события.

Кабинет обновляется при возвращении в окно, каждые 30 секунд и после собственных действий. Можно обновить страницу вручную.

## Реализованные требования

| Требование                 | Реализация                                                                                                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Две роли и авторизация     | Регистрация волонтёра/организации, вход, выход, редактирование профиля; серверная проверка роли и владельца                                                                                 |
| Каталог                    | Направления, поиск по названию/месту/организации, актуальные/предстоящие/прошедшие события, сортировка, избранное                                                                           |
| F1 — событие и ссылка      | Название, описание, категория, место, дата и время, часы, число мест, дедлайн, фото по HTTPS-ссылке, требования; отдельный URL события; редактирование и ручное закрытие                    |
| F1 — заявка                | Имя, университет/место работы, Telegram или email, мотивация, обязательное согласие; начальный статус Pending; защита от дублей                                                             |
| F1 — дедлайн               | Сервер отклоняет заявку после дедлайна или ручного закрытия независимо от состояния интерфейса; отдельный фоновый скрипт закрытия не требуется                                              |
| F2 — решения               | Принять/отказать, автоматическая отметка времени, уведомление в кабинете с правильным решением и следующим шагом                                                                            |
| F2 — вместимость           | Принятые и подтвердившие занимают места; при заполнении сервер блокирует дополнительное принятие и уведомление; можно увеличить вместимость                                                 |
| F2 — сообщения             | Отдельные шаблоны Telegram/email, копирование, отметка о фактической ручной отправке и её время; предупреждения после 44 ч. ожидания и 4 ч. после решения                                   |
| Метрика 48 часов           | В кабинете организации показывается доля всех заявок, для которых внешняя отправка отмечена не позднее 48 ч. после подачи; цель 80%. Встроенные уведомления не выдаются за внешнюю доставку |
| F3 — подтверждённый состав | Только Accepted → подтверждение самим волонтёром → Confirmed; время подтверждения, закрытый список и CSV; неподтвердившие отдельно и с предупреждением за 24 ч.                             |
| NFR1 — приватность         | Заявки и контакты доступны автору заявки и владельцу события; чужие организации и гости не получают состав/CSV; согласие проверяется сервером                                               |
| NFR2 — точность            | Решение и уведомление создаются одной транзакцией; подтверждение запрещено для Pending/Declined; тест с 10 заявками проверяет соответствие сообщений и состава                              |

Прямой запрос пользователя расширяет исходный concierge-MVP: сайт и самостоятельные личные кабинеты реализованы вместо Google Forms/Sheets. Telegram/email остаются ручными, как предусмотрено документом. **Автоматической внешней рассылки нет**: кнопка «Я отправил(а) сообщение» только фиксирует действие организатора. Чат, биллинг, реклама и проверка гипотезы о платёжеспособности не входят в MVP. Целевые показатели 15 организаций за 12 недель и повторных событий за 60 дней требуют настоящего пилота; демо-данные не подтверждают их достижение.

## Новая структура страниц

Ветка **`feat/platform-improvements-v2`** полностью обновляет интерфейс. Основной текст увеличен до 16–18 px, вспомогательные подписи — от 14 px. Главная стала короче, а каталог, регистрация, заявки, создание проектов, состав, статистика и профиль доступны на отдельных страницах.

- Гость начинает с `/`, находит проекты на `/projects` и регистрируется на `/register?role=volunteer` или `/register?role=organization`.
- Волонтёр видит персональный обзор, а свои заявки — на `/applications`. Подтверждение участия открывается в карточке заявки `/applications/:id`.
- Организация управляет проектами на `/my-events`, рассматривает отклики на `/requests`, собирает состав на `/roster`. Создание проекта — `/events/new`.
- Для авторизованных пользователей есть боковое меню; на телефоне оно открывается кнопкой меню. Роль отображается в шапке.
- Демо-вход находится на странице `/login`: раскройте **«Попробовать демо»**.

Полная карта страниц, принципы дизайна и ограничения: [docs/REDESIGN.md](docs/REDESIGN.md).

Скриншоты: [гостевая страница](docs/screenshots/home.png), [главная волонтёра](docs/screenshots/volunteer.png), [главная организации](docs/screenshots/organization.png), [каталог](docs/screenshots/projects.png).

Предыдущие версии сохранены в `feat/platform-improvements` и `feat/volunteer-platform-mvp`; метка исходного MVP — `mvp-baseline-2026-10-30`.

## Проверки

```bash
npm test            # 10 интеграционных тестов API, изолированная БД в памяти
npm run build       # TypeScript и production-сборка
npm run test:e2e    # 10 сценариев Chromium, включая страницы, роли, пагинацию, доступность и контраст
```

Браузерные тесты сами запускают изолированную пару серверов на 5174/3002 с отдельной временной SQLite-базой; рабочая БД не затрагивается. В облачной среде используется `/usr/bin/chromium`. Для другого пути задайте `CHROMIUM_PATH`. Если Chromium отсутствует, установите его или браузер Playwright и укажите путь.

## Хранение и конфигурация

- `.data/komek.sqlite` и WAL-файлы содержат пользователей, сессии, события, заявки и уведомления. Каталог исключён из Git. Сохраняйте его на постоянном диске и делайте резервные копии средствами SQLite; не копируйте только основной файл при активном WAL.
- `DATABASE_PATH` — необязательный путь к SQLite.
- `PORT` — порт API/production-сервера, по умолчанию 3001. Dev-прокси использует тот же порт.
- `SEED_DEMO=false` — отключить демонстрационные данные **до первого запуска пустой БД**. Для публичного экземпляра создайте отдельную чистую БД с этим параметром.
- `COOKIE_SECURE=true` — для публикации за HTTPS. Cookies HttpOnly и SameSite=Lax; пароли хешируются scrypt с индивидуальной солью; в БД хранится хеш токена сессии. Сессия действует 7 дней. Есть ограничение частоты регистрации/входа и проверка Origin для изменяющих запросов.

Пример запуска чистого экземпляра после сборки:

```bash
SEED_DEMO=false DATABASE_PATH=/persistent/komek.sqlite COOKIE_SECURE=true PORT=3001 npm start
```

Разворачивайте за HTTPS-прокси, сохраняющим исходный Host. Веб-приложение и API должны быть на одном origin. Для deep links сервер должен отдавать `dist/index.html` для страниц, кроме `/api` и статических ресурсов; `npm start` уже настроен таким образом. Перед реальным пилотом назначьте оператора персональных данных, укажите его контакт, проверьте согласие и правовые требования, настройте резервное копирование и используйте фотографии, на которые у организации есть права. Тексты в окнах конфиденциальности и условий обозначают статус пилота.

## Структура

- `src/main.tsx`, `src/App.tsx` — запуск приложения, маршруты и доступ по ролям.
- `src/state.tsx` — сессия, загрузка данных, обновления и уведомления.
- `src/pages/` — отдельные страницы платформы.
- `src/components/` — навигация, формы, карточки и общие элементы.
- `src/lib/` — API-клиент, навигация, пагинация и даты.
- `src/styles.css` — единая система оформления и адаптивная вёрстка.
- `server/app.js`, `server/db.js`, `server/index.js` — API, SQLite и production-сервер.
- `tests/api.test.js`, `tests/browser/platform.spec.ts` — интеграционные и браузерные проверки.
- `public/` — локальные фотографии, шрифт и значок сайта. Источники — [ASSETS.md](ASSETS.md).

## Посмотреть сайт через Render

В репозитории есть `render.yaml` для демо-сервиса с бесплатным планом. Это конфигурация публикации; сам файл не создаёт сервер и не является подтверждением выполненного развёртывания.

1. Войдите на https://dashboard.render.com/ через GitHub.
2. Выберите **New → Blueprint**, подключите репозиторий `Aiba-Djedai/Komek` и ветку **`feat/platform-improvements-v2`** для нового дизайна. У неё отдельный сервис **`komek-redesign-demo`**. Предыдущие версии доступны в `feat/platform-improvements` и `feat/volunteer-platform-mvp`.
3. Проверьте план **Free** и примените конфигурацию. Render установит Node.js 24, соберёт сайт и запустит API с интерфейсом одним сервером.
4. После успешного развёртывания откройте HTTPS-адрес сервиса, который покажет Render. Демонстрационные аккаунты доступны на странице входа в разделе «Попробовать демо».

Бесплатный сервис подходит для просмотра MVP: его SQLite-файлы временные, данные могут сбрасываться при пересоздании или повторном развёртывании, а первый запрос после простоя может ожидать запуска сервера. Для реальных пользователей нужен постоянный диск или отдельная постоянная база данных. Публичный URL и доступность публикации можно подтвердить только после выполнения развёртывания в аккаунте Render.
